本轮已实现微信小程序、Web后台及App共用页面。验收写入使用127.0.0.1:18085隔离演示库及虚构资料；18080仅更新版本并读取核对，没有写入本轮虚构订单、头像或续费意向。

## 功能与入口

| 功能 | 操作与结果 |
| --- | --- |
| 课程余额预警 | 家长成长首页 → 课程余额与今日订餐；按孩子、课程独立展示可用课时及预警线，等于预警线也提醒，包含退款预留影响 |
| 续费意向 | 每门课程可选“有意向续费 / 暂不续费”；老师和校长从工作台或全部应用的“课程与订餐”查看对应孩子、家长、课程与意向 |
| 今日订餐 | 家长选择今天订餐或不订餐；每个孩子每天一条，使用服务器当天与校区餐费，保存下单价格快照，不扣课程课时 |
| 二维码缴费 | 校长/老板在同页底部设置授权校区的餐费与收款码；家长查看二维码，未配置时显示提示 |
| 孩子头像 | 家长在课程与订餐页或孩子档案上传；教师/校长也可为授权学生上传，成长首页与名册显示，沿用媒体授权及文件权限 |
| 学生接送 | 取消定位与接送人人脸步骤；仍保留授权有效期、姓名、电话后四位、接送码、现场确认及异常拦截 |
| 日小结反馈 | 仅“满意 / 不满意”；不满意的原因必填，家长仅能反馈自己孩子已发布的小结 |

老师本人签到继续使用校区定位范围。取消的是学生到校及接送中的定位要求。

## 实际接口与页面验收

390×640浏览器App预览已走通家长、教师、校长操作：

1. 家长查看虚构学生陈一诺：晚辅余额12次，独立周末课程余额0次且预警；选择有意向续费后保存成功。
2. 家长选择今日订餐，校区餐费为18元，保存后显示已订餐；前后课程余额仍为12次和0次。
3. 家长日小结选择不满意，空白原因被拦截；填写原因后保存成功。
4. 切换老师、校长，均看到该学生、陈家长、周末课程的续费意向及当日一份18元的订餐记录。
5. 校长选择主校区、保存餐费成功；可选校区受服务端权限限制。
6. 使用虚构头像完成真实文件上传和关联。使用测试PNG核对缴费图片的访问票据及内容一致，随后清空配置，未使用或生成真实收款码。

页面截图保存在 `.run/family-services-shots/`，接口结果在 `.run/family-api-result.json`、`.run/family-ui-api-result.json`；会话凭据单独保存，不进入工程包。
