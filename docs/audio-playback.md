# 录音上传后播放修复

2026-10-27。

## 确认原因

后台附件组件将音频作为普通链接显示，没有音频播放器。上传表单同样只显示文件名，无法在提交前试听。

小程序上传区缺少试听入口；已保存附件原本有播放器，但需要统一上传试听与已保存附件的播放状态和生命周期处理。

现有一条用户上传MP3已验证完整：19928字节、单声道、16000Hz、时长3.321333秒。后端文件读取返回200，Range请求返回206，完整解码成功，因此不需要重新上传或修改后端文件。

## 后台修改

- AttachmentList按类型渲染原生audio/video控件，保留文件名链接与原授权地址。
- 上传表单复用附件播放器，上传后可试听并移除。
- 播放失败显示重新加载入口，同一列表播放新媒体时暂停上一项。
- 兼容旧附件缺少正确MIME但文件名带音频扩展名的情况。

## 验证

```bash
npm --prefix web run test:audio
npm --prefix web run build
```

回归测试使用真实Vue附件组件。修复前因缺少audio controls失败，修复后覆盖语音详情、可移除预览、旧MIME兼容和视频分类并全部通过。

浏览器打开现有“英语朗读练习”作业，用原录音实际验证：

- readyState=4，duration=3.321333，error=null。
- 点击播放后paused=false且currentTime递增。
- 最终ended=true、currentTime等于duration，无播放错误。

小程序回归入口：`node miniprogram/scripts/check-audio.js`；录音和权限回归：`node miniprogram/scripts/check-runtime.js`。微信真机扬声器输出仍需设备验收，模拟器测试不等同于真机听感验证。

## 2026-10-29：小程序播放仍无声

本地附件目录中的两条MP3均可完整解码：单声道、16000Hz，时长分别为5.429667秒和3.321333秒；平均音量分别为-19.6dB和-26.0dB，确认文件包含非零音频信号。此检查未证明手机实际收到或播放了对应文件。

共用 `file-list` 只设置了实例 `obeyMuteSwitch=false`。微信官方 `wechat-miniprogram/api-typings` 的 `types/wx/lib.wx.api.d.ts` 说明该属性从基础库2.3.0起不再生效，应使用 `wx.setInnerAudioOption`。修复后在首次播放、暂停后恢复及录音后试听时，先暂停当前音频，再通过该接口设置忽略静音开关、扬声器输出，并等待成功；播放器音量设为1。设置失败不启动播放，解码或网络错误在附件下显示错误码与重试提示。

新增回归先在原实现上复现3项失败，修复后覆盖全局输出、设置失败、迟到回调隔离、多条录音切换、已有的票据刷新与生命周期。测试模拟微信接口，不模拟设备扬声器；iPhone/安卓实际输出和蓝牙、耳机路由仍需真机复测。
