# 天健悦成长 拍照识题与错题入库方案

日期：2026-10-30；实施更新：2026-10-31。状态：小程序首版与本机专用OCR已实现，真实练习册准确率及真机操作尚未验收。

本次实现范围与实际结果见[首版验收记录](question-scan-acceptance-20261031.md)。已完成单页任务、方向处理、题框校对/拆合、勾选入库和裁图PDF；没有自动透视/弯曲展平、大模型补扫、自动批改或Web/App扫描新入口。下文保留后续完整规划，不把规划指标视为已实现或已测结果。

建议采用“独立部署的专用OCR与版面解析服务 + 本项目分题规则 + 老师勾选确认”的主方案。大模型作为低把握题目的补充识别方式。首版交付完整的“拍照、扫描、分题、校对、选择入库、打印”流程。

## 1 视频对应的产品行为

参考视频长约33.7秒，分辨率592×1280。以下按关键帧核对；录屏中的题目图可用于理解交互，不作为识别准确率的测试原图。

| 视频位置 | 已观察到的行为 | 本项目对应设计 |
| --- | --- | --- |
| 0秒及12至18秒 | 按日期排列扫描历史和图片缩略图 | 扫描记录按日期展示，保留学生、科目、待确认及已入库状态 |
| 3秒与21秒 | 展示整页照片及正在扫描状态 | 原图预览，显示上传、校正、识别、分题等实际阶段，可重拍 |
| 6秒与24秒 | 原图上出现若干题目区域 | 以题框和编号呈现候选题，点击后联动单题详情 |
| 9秒、27秒、30秒 | 选中题框高亮，底部题号切换，展开题目详情 | 上半部原图，下半部单题抽屉，支持勾选、调整范围、编辑题目 |

视频还包含判对错和讲解。本次先完成题目提取、分组与入库；“识别出一道题”不等于“判定它是错题”，由老师选择加入。自动批改、答案讲解作为后续独立能力。

尤其需要处理两种结构：语文阅读材料与多个小问共享上下文；数学页前一个章节的第7题与新单元的第1题共处一页。因此不能简单按数字或换行切题。

## 2 页面与操作

从教师工作台的某个孩子进入时，自动带入学生和班级。每次扫描先绑定一个孩子和科目，避免识别过程中切换孩子造成错误归档。知识点和错误原因允许后补，首屏不增加额外填写要求。

| 页面 | 首屏重点 | 操作及状态 |
| --- | --- | --- |
| 拍照识题 | 当前孩子、科目、拍照或相册按钮 | 拍照后裁边、旋转；提示模糊、反光、缺页边等质量问题；首版处理单页 |
| 扫描处理中 | 照片、扫描动效、当前阶段 | 显示“正在定位题目”“正在读取第几道题”等可核实状态；允许返回，稍后从扫描记录继续 |
| 题目选择 | 原图题框、横向题号、已选数量 | 点击题框或题号联动；默认不勾选；选中用蓝色，需复核用橙色，不用红绿颜色暗示判题结果 |
| 单题校对 | 题目裁图、识别文字、勾选按钮 | 编辑题干；调整题框；补框、拆分、合并；保留公式及图形；低把握处提示核对 |
| 入库结果 | 成功数量、失败题目及原因 | 进入错题本、继续扫描；重试只处理未成功项 |
| 扫描记录 | 日期、图片、孩子、处理状态 | 继续待确认任务，查看已导入题目，重试失败任务 |

视觉复用当前项目的柔和卡片、统一下拉组件、圆角按钮和底部抽屉。题目选择页仅保留“调整题目”“已选N题”“加入错题本”等高频操作。抽屉限高并内部滚动，底部操作避开安全区；不在该页面混入积分、续费和校区统计。

扫描线仅表示正在处理，不伪造百分比。服务尚未返回题框时不显示虚构题框；超时后明确显示失败、重试和手动框题入口。

## 3 技术选择

### 主方案 专用OCR与版面解析

使用PaddleOCR的文本识别与PP-StructureV3版面解析组件。PP-StructureV3提供文字、版面、公式、表格等可组合模块，并支持多栏阅读顺序恢复；这些能力适合作为本项目的识别底座。[PP-StructureV3官方文档](https://www.paddleocr.ai/main/en/version3.x/pipeline_usage/PP-StructureV3.html)

当前通用OCR官方文档列出PP-OCRv3至v6，默认组合为PP-OCRv6_medium。选型验证时比较与PP-StructureV3兼容的配置，固定软件及模型版本，不直接把不同版本组件混装，也不让运行环境自动追随最新版。[通用OCR官方文档](https://www.paddleocr.ai/main/en/version3.x/pipeline_usage/OCR.html)

| 方案 | 能提供什么 | 本项目仍需实现 | 采用位置 |
| --- | --- | --- | --- |
| PaddleOCR与PP-StructureV3 | 文字坐标、文字内容、版面区域及可选公式识别 | 练习册题目边界、大小题关系、共享材料、勾选入库 | 首选，先做样本验证 |
| RapidOCR与ONNX Runtime | 可离线部署的文字检测与识别，支持多平台集成 | 版面分组、公式及题目关系需要另行组合 | CPU及部署兼容性备选，不是完整分题产品 |
| Qwen3-VL | 图像文字、文档结构和区域定位能力 | 固定结果格式、坐标校验、原图对照和人工确认 | 次选，用于专用OCR低把握结果 |

RapidOCR官方说明了离线部署及ONNX等推理引擎支持；Qwen3-VL官方提供OCR、文档解析和定位示例。这些是组件能力说明，并非本项目习题识别效果的实测排名。[RapidOCR项目](https://github.com/RapidAI/RapidOCR)、[Qwen3-VL项目](https://github.com/QwenLM/Qwen3-VL)

### 分题流程

1. **图像准备**：检查格式、像素与文件大小；处理方向和EXIF旋转；裁去背景，做透视校正。书页弯曲严重时再评估展平模型。保留原始图，不覆盖原件。
2. **版面定位**：检测文字、公式、表格和配图区域，识别单栏或多栏结构，排除页眉页脚。
3. **文字识别**：输出文字块、坐标及识别评分。印刷题干与手写答案尽量分离；分不清时保留裁图并标为需核对，不自动擦除内容。
4. **题目组合**：结合题号、章节标题、缩进、间距、栏位和阅读顺序，将题干、选项、图形及相关公式合并为候选题。对阅读题保留材料与小问关系。
5. **老师确认**：用题框和文字展示结果；老师调整、勾选后，才生成正式错题记录。

公式可评测PP-FormulaNet等专用模型，输出LaTeX作为可编辑内容；复杂公式、竖式、几何图即使文字转换不可靠，也保留清晰裁图。原图内容优先，模型不补写看不清的数字、单位或条件。[公式识别官方文档](https://www.paddleocr.ai/main/en/version3.x/module_usage/formula_recognition.html)

通用版面模型识别的是文字、公式、图像等区域，不能直接视为完整题目检测器。本项目需要开发并验证上面的组合规则；如果真实样本中的误分、漏分仍超过目标，再标注习题区域，微调专用题块检测模型。训练样本与最终验收样本分开。

### 大模型补充识别

优先针对老师指定或规则标记的低把握题块调用Qwen3-VL；跨题关联不清时补充必要的页面上下文。处理结果进入同一个候选题结构，不单独建立第二套错题库。

结果必须能指回来源页和题框；对缺失或不清楚的内容返回“未识别”，不要求模型猜答案。校验结果结构、题目数量、题框范围、原始数字和单位；模型自报的置信度不作为准确率。老师能看到与原图的对照，模型建议不能覆盖已经确认的修改。

大模型模式默认关闭。可选择私有部署，或在明确配置外部服务后启用API；外部模式仅发送必要题图，并处理姓名、学号等无关信息。当前已有媒体授权不能直接解释为已同意发送给任意第三方。

## 4 分组规则与记录字段

| 维度 | 规则 |
| --- | --- |
| 学生归属 | 使用扫描任务创建时的学生及校区，后端重新校验；不让OCR猜孩子姓名并据此绑定 |
| 科目 | 默认继承老师选择，可在确认前修改；题型或知识点不确定时允许空缺 |
| 题目层级 | 保留章节、大题、小题关系；题号只用于显示，不能作为唯一ID |
| 阅读与综合题 | 材料作为共享上下文，选择某个小问时一起带上必要材料；导出多个同组小问时可共享展示一次材料 |
| 图形与选项 | 与所属题干一起裁取；不得只留题干丢掉图、表、选项或单位 |
| 跨页题 | 首版提示未完整并支持人工补充；后续多页阶段再自动关联 |
| 重复题 | 对同一孩子提示疑似重复，由老师判断是否继续保存；不跨家庭暴露题目或合并记录 |

建议最小增加两类业务记录，复用现有文件和错题表：

- **扫描任务**：任务ID、操作人、学生、校区、科目、来源文件、图像哈希、使用的模型版本、处理阶段、失败原因、创建及完成时间。
- **候选题**：候选ID、页序、排序、大题/小题编号、共享材料ID、题框、题目裁图文件ID、题干文字、公式内容、需核对原因、版本、已入库错题ID。

编辑前后分别保留识别结果和老师确认结果，便于追溯。题框坐标以校正后的标准页面为基准，并保存页面尺寸；缩放预览、拖框和服务端裁图使用同一坐标体系。弯曲展平涉及非线性变换时，不简单把题框缩放到原始照片上。

处理阶段：已上传 → 排队 → 校正/识别 → 待确认；异常分为失败、取消。入库状态单独记录为未入库、部分入库、全部入库，避免将“识别完成”误显示成“已保存错题”。

## 5 对接现有系统

已核对的现有能力：

- [小程序拍照录题](../miniprogram/pages/capture/index.js)已支持上传一张照片、手工编辑题目及保存。
- [TeachingService](../backend/src/main/java/cn/wanfu/TeachingService.java)的recognize目前固定返回NOT_CONFIGURED；saveCapture每次把一张照片保存成一条错题或作业。
- [MistakeBookService](../backend/src/main/java/cn/wanfu/MistakeBookService.java)可根据选中错题生成PDF，当前打印题目文字和所关联图片。
- [Web/App录题页](../web/src/views/CaptureView.vue)复用同一后端接口。

建议新增扫描任务接口，旧的手工录题和作业提交接口继续保留：

| 接口建议 | 用途 |
| --- | --- |
| POST /api/teaching-capture/jobs | 传入学生、科目及已上传文件ID；返回202与任务ID |
| GET /api/teaching-capture/jobs | 当前权限范围内的扫描记录 |
| GET /api/teaching-capture/jobs/{id} | 查询阶段、候选题和失败原因；小程序只在前台短轮询 |
| PATCH /api/teaching-capture/jobs/{id}/questions | 保存补框、拆分、合并、题干校对及候选版本 |
| POST /api/teaching-capture/jobs/{id}/import | 根据明确选中的候选ID及版本，逐题创建错题 |
| POST /api/teaching-capture/jobs/{id}/retry | 对允许重试的失败任务重新排队 |

入库复用现有创建错题逻辑。每个确认候选对应独立错题，附上题目裁图；来源整页放在任务里供追溯，不给每道错题重复挂整页照片。以任务、候选和学生建立唯一入库映射，连点与网络重试不重复新增。部分失败逐题显示结果，只重试失败项。

PDF首版以确认后的题目裁图为主要打印内容，带上必要材料并留订正空白，避免公式丢字和每道题重复打印整张作业。后续再增加可编辑文字与公式的精排版。打印来源保留学生原笔迹；清除答案或自动重建空白题不属于首版。

老师仅处理自己班级的孩子，校长限对应校区；家长查看绑定孩子已入库的错题。首版扫描入口沿用当前教师权限。扫描、结果查询、导入、裁图访问和PDF下载都校验权限与媒体授权；处理过程中撤回授权后，旧任务不能继续对外提供孩子的图像结果。

## 6 部署安排

主服务保持现有Java后端，增加一个内部OCR服务，运行在独立进程或容器中。手机仍只访问业务后端；OCR服务不直接暴露给小程序。Python服务输出结构化识别结果，题目归属、入库和文件授权由Java后端处理。

PaddleOCR官方已提供基于PaddleX的服务化方式，并建议先用基础服务验证，再按实际需求考虑更复杂的部署。首版优先复用这一能力；自定义分题逻辑只增加必要的处理代码，不同时部署多套推理平台。[官方服务化部署](https://www.paddleocr.ai/main/en/version3.x/inference_deployment/serving/serving.html)

首次部署建议：

1. 在独立测试目录/容器固定依赖、模型版本与权重哈希，提前下载模型并预热；运行时不反复下载或初始化。
2. Java持久化任务并用有界后台执行器调用OCR服务，限制并发；任务记录执行租约、超时与重试次数，进程重启后可恢复未完成任务。初期复用现有数据库，按需求再增加队列服务。
3. 图像只通过受控内部传输提供给OCR服务；不接受客户端任意URL，不把长期用户令牌交给识别服务。
4. 原图、校正图、裁图继承同一学生及校区权限；临时文件按任务清理，被正式错题引用的文件不误删。备份同时覆盖任务记录、错题和文件。
5. 通过真实样本及并发压测后，再把小程序配置切到该识别服务。停用时回到现有手工校对入口，保留已确认记录。

当前开发机为Apple M1 Pro、16GB内存，可作为CPU小样本验证候选，具体框架与模型兼容性需安装验证。正式部署先评估Linux 8核、16至32GB内存的CPU档位；这是试测资源建议，不是最低配置或性能保证。只有CPU测试无法达到选定等待时间和并发要求时，再评估GPU机器。

费用分为样本整理与标注、接入开发、服务器及存储、后续维护；主方案不依赖按次付费的大模型API。启用外部大模型后另设单页和每日调用预算。最终规格及费用需结合页面数量、同时扫描人数和样本耗时确定，不用官方单模块耗时替代整页端到端耗时。

## 7 实施阶段与交付条件

| 阶段 | 交付内容 | 进入下一阶段的条件 |
| --- | --- | --- |
| P0 样本验证 | 建议准备60张有授权的语数英作业原图，覆盖清晰印刷、混合手写、斜拍、阴影、双栏、图表和共享阅读材料；40张调试，20张留作独立复测 | 输出OCR与分题标注对照、错误分类、逐阶段耗时和资源占用，确定主模型及首版边界 |
| P1 首版闭环 | 单页扫描、题框与题号联动、共享材料分组、手工补框/拆合/校对、勾选批量入库、扫描历史及裁题PDF；小程序与Web/App对齐 | 业务、权限、重试及打印用例全部通过，样本结果达到约定目标 |
| P2 质量增强 | 多图批量、跨页题关联、复杂公式、练习册题块微调、打印精排 | 在保留验收集及新增难例上复测，质量提升且无明显退化 |
| P3 可选大模型 | 指定题块补充识别、私有模型或配置后的外部API、结果对比及调用预算 | 有证据改善低把握题目的可用率，且权限、费用及失败降级用例通过 |

P0后再据真实分题难度确定工期。视频原图里若包含教材题目、题干图形或笔迹，测试样本需保留这些真实干扰，不只使用干净排版的电子试卷。

## 8 验收口径

质量建议以“老师无需调整题框、补齐图形或重新归组，就能直接确认的题数 / 人工标注的完整题数”统计自动分题可用率。清晰印刷页可先设90%为讨论目标，最终以P0结果确认；它是拟定准入指标，不是本次已测结果。漏题、误合并、文字错误、公式与单位错误分别报告；手写、弯曲、反光等难例分组展示，不用一个总平均值掩盖失败场景。

| 验收场景 | 预期结果 |
| --- | --- |
| 同页多题、双栏、题号重启 | 每题拥有独立候选ID；阅读顺序合理，不因同题号覆盖、跳题或合并 |
| 阅读材料带多个小问 | 选择某个小问后仍带必要材料；选多个小问可作为同组查看与打印 |
| 选项、几何图、分数、单位和竖式 | 裁图完整；不可靠文字明确待核对，禁止自动补写条件 |
| 老师补框、拆分、合并和改题干 | 原图框、题号、列表及打印结果一致；老师修改不被迟到识别结果覆盖 |
| 只勾选第2和第5题 | 仅新增两条错题；未选择题目保留候选状态，不自动成为错题 |
| 连点保存、超时后重试、部分成功 | 成功项不重复，失败项可单独重试，可追溯对应候选 |
